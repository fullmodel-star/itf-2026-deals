## 商家總表（2026-11-04 起）

同一家公司在各表的寫法原本不一致，例如老爺有 12 種寫法、雲朗有 7 種，資料是散的。現在全部連到 `00_官方總覽/商家總表.csv`：

- **兩層**：
  - 「參展單位」是逛展時要去的那一攤，可能是集團、單一飯店、航空或旅行社，共 207 家，包含參展商名單上的全部單位。
  - 「旗下館」是集團底下的個別飯店，用「上層編號」指回所屬的參展單位。
  - 例如 H01 老爺酒店集團（M109）底下有 H01-01 北投老爺酒店等 7 館。
- **連結方式**：住宿、餐飲、機票、跟團、限時搶購、參展商名單 6 張表，都在名稱欄後面多一欄「商家編號」。
  - 機票：航空欄寫的是具體航空公司，就連到該航空；寫「—／依產品／多家」的，連到銷售的旅行社或平台。
- **畫面**：
  - 住宿、餐券依商家合併成一張卡（住宿 177 筆 → 50 家，餐券 185 筆 → 36 家），方案多的先列最便宜的 5 個。
  - 卡片下方有「這家還有：餐券 6 筆 ›」，點了跳到該分類，而且只看這一家。
  - 全站搜尋打公司名稱，會先列出這家公司在各分類的筆數。
- **比對規則**寫在 `_工具/link_merchants.py` 開頭。
  - 名稱要和總表的「商家名稱」或「對應名稱」（用；分隔）完全相同。
  - 名稱對不到時，改用攤位號找，並列出來請人確認。
  - 兩種都對不到就報錯，`build.py` 會拒絕建置。
- **例外**：
  - 多家合賣的券（例如王品／瓦城／欣葉）連到 X01「多家聯合」。
  - 不在寒舍旗下、但記載在寒舍攤位販售的豐邑集團，列為寒舍攤位下的一筆，備註寫明。

## 更新資料

1. 修改各資料夾的 `.csv`（新增、修改價格都可以）。新的一筆「商家編號」可以先留空。
2. 執行 `python _工具/link_merchants.py` 自動補上商家編號。
   - 若出現「對不到商家總表」：把那個寫法加進總表中正確商家的「對應名稱」。
   - 若是全新的商家：在總表新增一列。
   - 改完重跑這一步。
3. 有新截圖就放進該資料夾的 `截圖\`，再執行 `python _工具/shrink_shots.py` 壓成 JPG。
4. 執行 `python _工具/build.py` 重新產生 `index.html`。
5. 部署到 Cloudflare（部署包只收白名單裡的檔，規則寫在 `_工具/build_staging.py`）：
   ```
   python _工具/build_staging.py <暫存資料夾>
   npx wrangler pages deploy <暫存資料夾> --project-name=itf-2026-deals --branch=main
   ```
6. commit 並 push 到 GitHub 留存（GitHub 只負責版控和舊網址轉址）。

也可以直接請 Claude 做以上步驟。
